# 自学路线图：一个人从零做完这个项目

> 这份文档回答的是"怎么把能力长出来"，不是"每天做什么"。
> 任务清单看 `B模块作战手册.md`，这里讲的是**学习顺序和方法**。

---

## 0. 先算一笔账（别骗自己）

| 项目 | 数字 |
|---|---|
| 三人 × 8 周 × 6 小时 | 约 **144 人时** |
| 你一个人做完全部 | 需要 **8 周 × 18 小时/周** |
| 如果你也只有 6 小时/周 | 总量只有 48 小时，**做不完原版** |

**结论：一个人做，必须砍范围。** 见第 3 节。

但有个好消息：**一个人做的项目，答辩时反而更好讲。**
没有"这块不是我做的"这种尴尬，老师问到哪你都能答。很多老师其实更喜欢单人项目，因为问得深。

## 1. 六个阶段，顺序不能跳

| 阶段 | 学什么 | 完成标志（必须做出东西） |
|---|---|---|
| **一、Unity 操作** | 界面四块、GameObject/Component、Transform、Prefab 概念 | 建一个 Cube 挂脚本，**按 Play 它会动** |
| **二、最小够用 C#** | 只学第 4 节那 8 个概念，**不要系统学 C#** | 能用变量控制方块的速度和方向 |
| **三、车辆物理** | Rigidbody、WheelCollider、FixedUpdate | **车能用手开**，不翻车 |
| **四、射线感知** | Physics.Raycast、LayerMask、Gizmos 调试 | 前方有障碍时 Console 打出距离 |
| **五、决策与可视化** | 转向计算、速度规划、UI、LineRenderer | 车自己沿路径跑，遇障碍停，界面有数字 |
| **六、表达** | 报告结构、录屏、PPT | 3 分钟演示视频 + 能讲清每个模块 |

**铁律：上一阶段的"完成标志"没做到，不要开下一阶段。**
跳阶段的后果是：你会在阶段四同时卡在"Unity 不会用 + C# 不会写 + 射线不懂"，然后放弃。

## 2. 独狼版 8 周计划

假设你每周能投入 **12~15 小时**（一个人做需要这个量级）：

| 周 | 主题 | 验收 |
|---|---|---|
| 0 | Unity 操作 + 最小 C# | 方块会动、会转向 |
| 1 | 场景 + 车模型 + WheelCollider | 车能跑，能转弯（手动） |
| 2 | 射线检测 + Waypoint 摆放 | 8 个路径点画出来了，射线能测距 |
| 3 | **核心闭环**（最关键的一周） | 车自动沿路径跑 + 遇障碍减速 + 界面显示数据 |
| 4 | 可视化 + UI 完善 | 路径线、射线、速度显示、报警灯 |
| 5 | 稳定性 + 边界处理 | 连跑 5 分钟不崩、冲出道路能恢复 |
| 6 | 录演示视频 + 报告初稿 | 视频 3~5 分钟，报告 60% 完成 |
| 7 | 报告定稿 + PPT + 演练 | 全部交付物齐全 |

**第 3 周是生死线。** 那一周跑通了，后面都是锦上添花；那一周没跑通，后面全是救火。

## 3. 一个人做，必须砍掉这些

| 砍掉 | 理由 |
|---|---|
| ❌ MATLAB 联动 | 锦上添花，不是数字孪生的必要条件 |
| ❌ A* 寻路 | Waypoint 跟踪已经够了，A* 是加分项不是及格项 |
| ❌ 多视角切换 | 保留第三人称 + 俯视两个就够 |
| ❌ 场景美化 | Cube 搭路 + 官方车模型，别碰美术 |
| ❌ 物理精调 | 车不翻、不打滑就行，别追求真实手感 |
| ❌ 多车跟驰 | 一辆车跑通就是完整闭环 |

**必须保住的（少一个都不叫自动驾驶）**：
车能动 → 能感知前方 → 能沿路径走 → 遇到障碍会减速 → 界面能看到数据

## 4. C# 最小够用集：只学这 8 个

**不要去买本《C# 从入门到精通》。** 你只需要这些：

1. **变量与类型** —— `float speed = 6f;`（注意 `6f` 的 f）
2. **if / else** —— 决策全靠它
3. **方法** —— `void Update()` 是什么、怎么自己写一个
4. **类的字段与属性** —— 为什么 Inspector 里能拖引用（`public Transform target;`）
5. **Vector3** —— `.x .y .z`、`Vector3.forward`、加减乘
6. **Transform** —— `.position` `.rotation` `.forward`、`Translate()` `Rotate()` `LookAt()`
7. **List / 数组** —— 存 8 个路径点用
8. **Update vs FixedUpdate** —— 物理相关的必须放 FixedUpdate

遇到不懂的语法再去查，别提前学。**提前学的东西两天就忘，用的时候查的才记得住。**

## 5. 学习方法：8 条（比资源重要一百倍）

**① 20 分钟法则**
卡住超过 20 分钟，立刻去搜 / 问 AI / 问同学。**死磕是最慢的学习方式。**
我见过太多人一个报错卡三天，最后发现是引用没拖。

**② 先抄跑通，再改，再理解**
顺序是：抄一份能跑的 → 改一个参数看变化 → 改一段逻辑 → 最后才去想"为什么"。
反过来（先理解再动手）对零基础是灾难。

**③ 一个概念 = 一个最小实验**
学 Raycast？就建一个 Cube 射另一个 Cube，看到 Console 打出距离，完事。
不要"学完 Unity 再做项目"。

**④ 报错是最好的教材**
Console 里双击红色报错会跳到出错的那一行。**90% 的错误是"引用没拖"和"名字拼错"。**

**⑤ 一次只改一处**
改了三处然后崩了，你不知道是哪处的锅。**改一处 → 测 → 再改。**

**⑥ 每完成一个小功能就 commit**
`git commit -m "车能转弯了"`。既是备份，也是你最后写"开发过程"章节的素材。

**⑦ 每天最后 10 分钟写笔记**
写三行：今天做了什么、卡在哪、明天做什么。
**八周后把这些笔记拼起来，就是报告的"开发过程"章节。** 不用熬夜补。

**⑧ 教程最多看到一半就动手**
看教程会产生"我懂了"的错觉。动手才会发现你没懂。

## 7. 每天 2 小时怎么花

| 时长 | 做什么 |
|---|---|
| 10 min | 看昨天的笔记，确认今天要做什么 |
| 70 min | **动手做**（这是唯一重要的部分） |
| 30 min | 调试 / 处理报错 |
| 10 min | 写今天的笔记 + commit |

**动手的时间必须占一半以上。** 如果你一天都在看教程，那天的进度是零。

## 8. 答辩自检：这 10 个问题你要能答出来

能答出来 = 你真学会了。答不出来 = 你是复制粘贴的，老师一问就露馅。

1. 为什么用 WheelCollider 而不是直接改 `Transform.position`？
2. 单条射线有什么局限？斜前方的车能发现吗？
3. 转向角是怎么算出来的？（提示：`InverseTransformPoint` + `Atan2`）
4. `arrivalRadius` 设大了会怎样？设小了呢？
5. 车到终点为什么会来回抖？怎么解决？
6. 你的速度决策逻辑是什么？为什么不用 PID？
7. `Update` 和 `FixedUpdate` 有什么区别？为什么物理要放 FixedUpdate？
8. Unity 的坐标系是怎样的？（左手系，Y 轴向上，Z 轴向前）
9. 你的系统最可能在什么场景下失效？
10. 如果重做一次，你会改哪里？

**第 9、10 题是加分题。** 能诚实说出自己系统的局限，老师反而会觉得你真懂了——
只会吹"我的系统完美运行"的，一看就是没做过。

## 9. 自学者最容易踩的 6 个坑

| 坑 | 表现 | 怎么避 |
|---|---|---|
| **教程地狱** | 看了 20 小时教程，一行代码没写 | 教程看到一半就动手 |
| **复制粘贴不理解** | 跑通了但老师一问就懵 | 每抄一段，改一个参数看变化 |
| **一次改太多** | 崩了不知道是哪处的锅 | 一次只改一处 |
| **不用版本管理** | 改崩了回不去 | 每完成一个功能 commit |
| **最后一周才集成** | 三个模块拼不起来 | 第 3 周就必须跑通闭环 |
| **追求完美** | 车不真实、场景不好看，卡一周 | 先跑通，再优化；及格优先 |

## 最后一句

这个项目的难点**不在技术，在坚持到第 3 周**。

前两周你会觉得什么都不懂、进度为零——这很正常，每个人都是这样。
但只要第 3 周那个瞬间来了——**方块自己沿着路径跑起来，遇障碍自己停**——
你会突然明白所有的东西是怎么串起来的。那一刻之前是煎熬，之后是加速度。

**别在第 2 周放弃。** 那是放弃人数最多的一周，也是离突破最近的一周。
