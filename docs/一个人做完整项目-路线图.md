## 一、先说清楚：Demo 是什么

**Demo = demonstration（演示）**，指一个能打开、按一下就能看到完整效果的东西。

你这个项目的 Demo 长这样：

> 打开 Unity，按 ▶ Play → 一辆车自己沿着路线跑 → 遇到障碍物自动减速停车 → 旁边 MATLAB 图窗实时画着速度曲线 → 数据面板显示实时状态。

它和报告的分工：

| | 是什么 | 什么时候用 |
|---|---|---|
| **Demo** | 能跑的程序 | 答辩现场演示、录视频 |
| **报告 / PPT** | 文字、图表、截图 | 交作业、讲原理 |

答辩时老师通常第一句就是"演示一下看看"。**Demo 跑不起来，报告写得再好也救不回来。**

## 二、数字孪生是什么，你的孪生体长什么样

### 三要素

**数字孪生 = 给真实的东西配一个数字分身，两者实时连着线。**

| 要素 | 含义 | 在你项目里对应 |
|---|---|---|
| **物理实体** | 真实存在的东西 | Unity 里那辆在跑的车（带传感器） |
| **虚拟模型** | 数字空间里的副本，用数学描述它"该怎么动" | MATLAB 里的一阶惯性模型 |
| **数据连接** | 两者持续互相传数据 | UDP 双向，20Hz |

缺了第三条就只是个"模型"，不叫孪生。

### 你的架构

```
        ┌─────────────────────────┐
        │  物理实体侧：Unity       │
        │  车在跑、有射线传感器     │
        └───────────┬─────────────┘
                    │  ① 上行：状态 20Hz（JSON）
                    │     位置/速度/转向/前车距离/路标点
                    ▼
        ┌─────────────────────────┐
        │  虚拟模型侧：MATLAB      │
        │  ① 决策：按距离定目标速度 │
        │  ② 孪生模型：一阶惯性推演 │
        │  ③ 对比：模型 vs 实际     │
        └───────────┬─────────────┘
                    │  ② 下行：指令（JSON）
                    │     目标速度 / 强制刹车
                    ▼
              Unity 执行，闭环成立
```

**"双向"体现在**：Unity 把状态发上去，MATLAB 算完把**目标速度**发回来，Unity 真的照着执行。这就是"虚拟端反向控制实体"。

### 孪生体到底是什么

MATLAB 里那个"一阶惯性模型"：

```
v_model(k+1) = v_model(k) + (v_des - v_model(k)) × dt / TAU
```

意思是"车不会瞬间达到目标速度，中间有个时间常数 `TAU`"。这个模型独立推演自己的速度和里程，然后和 Unity 的实际数据对比：

- **速度偏差 RMS** —— 越小说明模型越准
- **累计里程差异** —— 反映模型的累积误差

**标定 `TAU` 就是你报告里的实验内容**：改几个值，看哪个偏差最小。

## 三、你的项目范围（砍掉什么，为什么）

### 三个模块怎么办

| 模块 | 原计划做法 | 一个人版做法 | 为什么这么改 |
|---|---|---|---|
| **A 车辆** | WheelCollider 真实物理 + CarController | **运动学小车**（直接移动 Transform） | WheelCollider 调参是出了名的玄学，一个人零基础做能烧 20+ 小时还可能翻车。运动学小车演示效果一模一样 |
| **B 感知规划** | 单射线 + Waypoint + 路径跟踪 | **原样保留，别动** | 已经写完了，是三块里技术含量最高的部分 |
| **C 控制可视化** | 速度控制 + UI + 场景集成 | 简化为 **AutoDriver + 一个数据面板** | 模块隔离是为了让三个人并行开发。你一个人做，直接串起来 |
| **数字孪生** | MATLAB 联动（原计划第 5 周起） | **提前到第 4-5 周，且必须在第 1 周先验通信** | 老师硬性要求，是核心不是加分项 |

### 明确不做（省下的时间就是你活下来的资本）

- **多视角相机切换** —— 好看但不加分
- **美术** —— 车用 Cube 拼就行，不用找模型
- **精美的 UI 面板** —— 几个文字显示数字就够
- **Simulink 建模** —— 老师说的是"MATLAB 或 Simulink"，用 MATLAB 脚本省一大截时间

### 保留但简化

- **UI**：几个文字显示数字
- **可视化**：路径用球和线、射线用 LineRenderer

## 四、7 周计划（每周 6 小时）

### 第 1 周（9/22 - 9/28）· 6h —— B 验收 + 验掉最大风险 + 造车

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 1h | 跑通 B 测试场景（含遇障绕行） | Console 出现"启动绕行 / 绕行结束"，车能跑完整圈 |
| **1h** | **MATLAB 通信冒烟测试** | MATLAB 图窗出现曲线，Unity Console 显示"已收 N 包" |
| 2h | 做一辆"看起来像车"的车：车身 + 4 个轮子 + 车头标记 | Scene 视图里一眼能认出是辆车 |
| 1.5h | 给车加运动学控制（能手动 WASD 开） | 按 W 前进、按 A/D 转向 |
| 0.5h | 保存场景、提交代码 | 仓库里有当周提交记录 |

> **为什么第 1 周就要碰 MATLAB？** 因为 UDP 通信是**整个项目风险最高的部分**（防火墙、端口、IP、JSON 格式，任何一处不对都通不了）。风险最高的东西要**最早验掉**——如果第 4 周才发现通不了，你只剩 2 周补救。

### 第 2 周（9/29 - 10/5）· 6h —— 车能自动跑

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 3h | `CarController`：把 WASD 换成 `SetInput(steering, motor, brake)` | 用代码能控制车前进转向 |
| 3h | `AutoDriver`：读 B 的 `Steering`，转成车的输入 | **按 Play，车自己沿 8 个路标点跑圈** |

**这是整个项目的关键里程碑。** 到这一步，"自动驾驶"就成立了。

### 第 3 周（10/6 - 10/12）· 6h —— 避障闭环 + 数据面板

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 3h | 把 `FrontCarDetector` 接到刹车：近了减速、很近刹停 | 路上放障碍，车会减速停车 |
| 3h | `TelemetryPanel`：显示速度 / 前车距离 / 当前目标点 / 状态 | 屏幕上有实时数字 |

**到这一步，自动驾驶 Demo 已经可以拿去演示了。** 后面都是数字孪生和加分项。

### 第 4 周（10/13 - 10/19）· 6h —— 孪生体上线（单向）

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 1h | 把 `MatlabUdpBridge` 正式挂到车上，接好 car / detector / follower 引用 | Console 显示"MATLAB 连接 = 是" |
| 2h | 跑 `matlab/unity_bridge.m`，确认三张曲线都在动 | 速度、前车距离、累计里程三条线实时刷新 |
| 2h | 让 MATLAB 的指令**真正生效**：`AutoDriver` 读 `GetDesiredSpeed()` | 改 MATLAB 里的 `V_MAX`，Unity 里车的速度跟着变 |
| 1h | 存一次 CSV，看数据格式 | `twin_log_*.csv` 里有完整数据 |

**验收核心**：在 MATLAB 里把 `V_MAX` 从 8 改成 3，Unity 里的车立刻慢下来 —— 这就证明"虚拟端能控制实体"。

### 第 5 周（10/20 - 10/26）· 6h —— 孪生体标定 + 双向闭环

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 2h | 标定 `TAU`：试 0.5 / 1.2 / 2.5 / 4，记录速度偏差 RMS | 一张表，找出偏差最小的值 |
| 2h | 完善反向控制：MATLAB 的刹车指令要能真的刹住车 | 障碍物前 MATLAB 发 brake，车停下 |
| 1h | 掉线降级测试：关掉 MATLAB，车要能自己继续跑 | 断开后 Console 显示"连接 = 否"，车不失控 |
| 1h | 把曲线图、CSV 截图存好（报告素材） | 有图有表 |

> **掉线降级很重要**：如果 MATLAB 一关车就傻了，答辩时老师会问"那你这个系统可靠吗"。代码里已经做了 `IsConnected` 判断，你要验证它真的有效。

### 第 6 周（10/27 - 11/2）· 6h —— 主场景 + 报告 + PPT

| 时间 | 做什么 |
|---|---|
| 2h | 搭 `Main.unity`：道路、路标、障碍物摆整齐，相机调整到位 |
| 3h | 写报告（结构见下） |
| 1h | 做 PPT + 录 3 分钟演示视频（备用，防现场翻车） |

报告结构：

1. 项目背景与目标
2. **系统架构**：三模块 + 数字孪生的数据流（画框图）
3. **车辆模型**：运动学模型（说明为什么不用动力学，这是取舍不是偷懒）
4. **感知模块**：射线检测原理 + 几何图（车头射线、夹角、距离）
5. **规划模块**：Waypoint 路径跟踪 + `InverseTransformPoint` / `Atan2` 核心代码
6. **数字孪生**：三要素、UDP 协议、孪生模型公式、`TAU` 标定过程与结果
7. **实验与结果**：第 5 周的数据表 + 曲线截图
8. **局限与改进**：单射线看不到斜前方 → 未来做多射线 / A*

### 第 7 周（11/3 - 11/9）· 6h —— 打磨与答辩准备

| 时间 | 做什么 |
|---|---|

## 五、进度落后时，按这个顺序砍

从下往上砍，砍到能交付为止：

1. 多视角 / 相机切换
2. 第 5 周只标定 `TAU`，放弃掉线降级测试
3. 第 6 周的主场景美化砍掉，直接用 B 的测试场景演示
4. UI 精简到只剩"速度 + 前车距离"两个数字
5. 路径可视化保留、射线可视化砍掉
6. 报告里的实验章节改成描述性文字（不贴数据表）

**绝对不能砍的底线**：车能自动沿路径跑 + 遇障碍能减速停车 + MATLAB 能看到曲线 + MATLAB 能反向控制车速。

> 注意最后一条：**数字孪生是老师硬性要求的，砍到只剩骨架也得留**。

## 六、答辩可能被问到的问题（提前准备）

1. 为什么用射线而不是碰撞体做感知？
2. `InverseTransformPoint` 是干什么的？为什么需要它？
