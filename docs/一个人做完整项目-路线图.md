# 一个人做完整项目 · 路线图（6-7 周版）

> 背景变化：原计划三人分工（A 车辆场景 / B 感知规划 / C 控制可视化），现在由你一个人完成。
> 现实约束：**剩余 6-7 周，每周约 6 小时，总计约 40 小时**。
> 原三人版总工作量约 144 人时 —— 所以这不是"努力一点就能扛下来"，而是**必须砍掉一半以上**。

---

## 一、先说清楚：Demo 是什么

**Demo = demonstration（演示）**，指一个能打开、按一下就能看到完整效果的东西。

你这个项目的 Demo 长这样：

> 打开 Unity，按 ▶ Play → 一辆车自己沿着路线跑 → 遇到障碍物自动减速停车 → 屏幕旁边实时显示速度、前方障碍距离、当前目标路标点。

它和报告的分工：

| | 是什么 | 什么时候用 |
|---|---|---|
| **Demo** | 能跑的程序 | 答辩现场演示、录视频 |
| **报告 / PPT** | 文字、图表、截图 | 交作业、讲原理 |

答辩时老师通常第一句就是"演示一下看看"。**Demo 跑不起来，报告写得再好也救不回来。**

## 二、你的项目范围（砍掉什么，为什么）

### 三个模块怎么办

| 模块 | 原计划做法 | 一个人版做法 | 为什么这么改 |
|---|---|---|---|
| **A 车辆** | WheelCollider 真实物理 + CarController | **运动学小车**（直接移动 Transform） | WheelCollider 调参是出了名的玄学，一个人零基础做这个能烧掉 20+ 小时还可能翻车。运动学小车演示效果一模一样 |
| **B 感知规划** | 单射线 + Waypoint + 路径跟踪 | **原样保留，别动** | 已经写完了，是三块里技术含量最高的部分 |
| **C 控制可视化** | 速度控制 + UI + 场景集成 | 简化为 **AutoDriver + 一个数据面板** | 模块隔离是为了让三个人并行开发。你一个人做，直接串起来，少一层绕路 |

### 明确不做（省下的时间就是你活下来的资本）

- **MATLAB 数字孪生联动** —— 原文档自己写了"前 6 周不要碰"，40 小时根本不够
- **多视角相机切换** —— 好看但不加分
- **美术** —— 车用 Cube 拼就行，不用找模型

### 保留但简化

- **UI**：几个文字显示数字，不做精美面板
- **可视化**：路径用球和线、射线用 LineRenderer，够看就行

## 三、7 周计划（每周 6 小时）

### 第 1 周（9/22 - 9/28）· 6h —— B 模块验收 + 造一辆车

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 1h | 跑通 B 测试场景（含遇障绕行） | Console 出现"启动绕行 / 绕行结束"，车能跑完整圈 |
| 2h | 做一辆"看起来像车"的车：车身 + 4 个轮子 + 车头标记 | Scene 视图里一眼能认出是辆车 |
| 2h | 给车加运动学控制（能手动 WASD 开） | 按 W 前进、按 A/D 转向 |
| 1h | 保存场景、提交代码 | 仓库里有当周提交记录 |

### 第 2 周（9/29 - 10/5）· 6h —— 车能自动跑

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 3h | `CarController`：把 WASD 换成 `SetInput(steering, motor, brake)` | 用代码能控制车前进转向 |
| 3h | `AutoDriver`：读 B 的 `Steering`，转成车的输入 | **按 Play，车自己沿 8 个路标点跑圈** |

**这是整个项目的关键里程碑。** 到这一步，"自动驾驶"就成立了。

### 第 3 周（10/6 - 10/12）· 6h —— 避障闭环 + 数据面板

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 3h | 把 `FrontCarDetector` 接到刹车：近了减速、很近刹停 | 路上放障碍，车会减速停车 |
| 3h | `TelemetryPanel`：显示速度 / 前车距离 / 当前目标点 / 状态 | 屏幕上有实时数字 |

**到这一步，Demo 已经可以拿去演示了。** 后面都是加分项。

### 第 4 周（10/13 - 10/19）· 6h —— 主场景 + 可视化打磨

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 3h | 搭 `Main.unity`：道路、路标、几个障碍物，摆得像个测试场 | 场景看起来完整、不乱 |
| 2h | 路径可视化（已跑灰 / 未跑青）、射线用 LineRenderer 显示在 Game 视图 | 演示时能看到"车在想什么" |
| 1h | 相机调整到能看全全局 | 按 Play 一眼看明白 |

### 第 5 周（10/20 - 10/26）· 6h —— 实验与数据（报告素材）

| 时间 | 做什么 | 验收标准 |
|---|---|---|
| 2h | 实验一：不同障碍距离下车的响应（5 组数据） | 一张表格 |
| 2h | 实验二：`steerGain` 取 1 / 2 / 3 / 5 的轨迹差异 | 截图 + 结论 |
| 2h | 实验三：检测距离 20 / 10 / 5 米的表现 | 截图 + 结论 |

**这些表格和截图就是你报告里最有说服力的部分**，老师最想看"你试过什么、为什么选这个值"。

### 第 6 周（10/27 - 11/2）· 6h —— 报告与 PPT

| 时间 | 做什么 |
|---|---|
| 3h | 写报告（结构见下方） |
| 2h | 做 PPT（一页一个要点，别堆字） |
| 1h | 录演示视频（3 分钟以内，备用，防现场翻车） |

报告结构（一个人做，每章都要写）：

1. 项目背景与目标
2. **系统架构**：三个模块怎么串起来的（画一张框图）
3. **车辆模型**：运动学模型（说明为什么不用动力学，这反而显得你懂取舍）
4. **感知模块**：射线检测原理 + 几何图（车头射线、夹角、距离）
5. **规划模块**：Waypoint 路径跟踪 + `InverseTransformPoint` / `Atan2` 核心代码
6. **控制与可视化**：数据流、UI 设计
7. **实验与结果**：第 5 周的数据表
8. **局限与改进**：单射线看不到斜前方 → 未来做多射线 / A*

### 第 7 周（11/3 - 11/9）· 6h —— 打磨与答辩准备

| 时间 | 做什么 |
|---|---|
| 3h | 修 Demo 里剩下的毛病，确保连跑 5 分钟不崩 |
| 2h | 准备答辩问题（见下方清单） |
| 1h | 最终检查：报告、PPT、视频、代码全部齐全 |

## 五、答辩可能被问到的问题（提前准备）

1. 为什么用射线而不是碰撞体做感知？
2. `InverseTransformPoint` 是干什么的？为什么需要它？
3. 为什么用 `Atan2` 算转向角，不用 `Vector3.Angle`？
4. 你的转向系数 `steerGain` 怎么定下来的？
5. 车在什么情况下会失效？（答：单射线看不到斜前方、静止障碍物外的弯道、急弯）
6. 如果要做得更好，下一步会做什么？
7. 为什么用运动学模型而不是 WheelCollider？（答：课程重点在感知与规划，动力学不是本课题范围）

## 六、每周的固定动作

git checkout dev-B
git pull origin dev-B

**收工时：**

1. Unity 里 `Ctrl + S` 保存场景（标题栏没有 `*` 才算存好）
