# GitHub 参考项目清单

> 按"对 B 的价值"排序。原则是**看结构、抄思路、自己写**——整段复制会在答辩翻车，
> 而且这些代码普遍比你需要的复杂 5 倍。

## 一、必看（直接对应你的模块）

### 1. Unity Standard Assets — `WaypointProgressTracker` + `WaypointCircuit`

| | |
|---|---|
| 地址 | https://github.com/IncentWang/Unity-Standard-Assets |
| 关键文件 | `Standard Assets/Utility/WaypointProgressTracker.cs`、`WaypointCircuit.cs`<br>`Standard Assets/Vehicles/Car/CarAIControl.cs` |
| 另一份副本 | https://github.com/udacity/self-driving-car-sim （Udacity 模拟器自带，路径 `Assets/Standard Assets/Utility/`） |
| 许可 | Unity Companion License（学习/参考 OK，不能整体二次分发） |

**这是你模块的祖师爷。** 值得偷的东西：

- `ProgressStyle` 两种模式：
  - `PointToPoint` — 到一个点换下一个（**你现在的方案，课设够用**）
  - `SmoothAlongRoute` — 沿路线按距离平滑推进（弯道更顺，第 5 周有余力再升级）
- **前视距离（look-ahead）**：`lookAheadForTargetOffset + lookAheadForSpeedFactor * speed`
  速度越快看得越远——这是你报告里能写的一句高级话
- `OnDrawGizmos` 里画绿线（车→目标点）和黄线（目标点朝向），可直接学

**别抄的**：`WaypointCircuit` 里的 Catmull-Rom 曲线插值 + 缓存采样表，200 行，
8 个路径点的课设用不上，抄了你也讲不清。

### 2. Avit-Rai/Autonomous-Car

https://github.com/Avit-Rai/Autonomous-Car

单文件 `RobotController.cs`，作业性质，结构和你的需求几乎一样：

```
Sense() → HandleCarSteering() → HandleCar() → WheelsUpdate()
```

值得看：**怎么写"传感器 → 转向决策"这一段的 if-else**。
它是三射线（前 / 左 / 右），你只有一条——但判断逻辑的组织方式可以直接借鉴。
README 写得挺完整，抄它的报告结构不亏。

---

### 3. SreenikethanNG/Autonomous-Robot-Navigation-Unity

https://github.com/SreenikethanNG/Autonomous-Robot-Navigation-Unity

也是一个 `RobotController.cs`，8 个传感器：`FRS`（前）、`L1S~L3S`（左）、`R1S~R3S`（右）、`ORS`（朝向）。
附带 `RobotNavigation.mp4` 演示视频——**可以照着学你的演示视频怎么录**（3-5 分钟、一镜到底、配解说）。

## 三、别碰的坑

- **ML-Agents / 强化学习类项目**（如 `Amit-1216/autonomous-car-simulation-mlagents`）：
  需要训练、Python 环境、神经网络。答辩老师问一句"你的 reward function 怎么设计的"就死。
- **完整游戏项目**（几百个文件、自定义渲染管线）：跑都跑不起来。
- **`.unitypackage` 而不是源码的项目**：看不到代码，学不到东西。

## 四、自己找项目的关键词

```
unity waypoint follower car
unity raycast obstacle avoidance
unity autonomous vehicle simple

unity sensor visualization linerenderer
```

筛选技巧：加 `stars:>50`、看 `pushed_at`（两年内）、看文件数（<50 个文件的先翻）。

## 五、正确姿势

1. 找到项目 → 只打开它的核心 .cs 文件
2. 看懂它 `Update()` 里的主干逻辑（通常 20~40 行）
3. **关掉它，自己写一遍** — 写不出来说明没看懂，回去看
4. 跑通后再回来对比，看人家处理了什么你没想到的边界情况
5. 报告"相关工作"一节里注明参考来源和链接

> 一句话：**抄思路不丢人，抄代码才丢人；而且抄来的代码你答不出问题。**
